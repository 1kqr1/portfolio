## 4. Next.js のハイドレーションJSを取り除いた判断（要確認）

### 何が起きたか

Next.js への移行を完了した直後（コミット `fcd871e`）の実測値は、**目標を大きく下回っていた**:

| | 移行直後 | 目標 |
|---|---|---|
| Performance | 87 | 95以上 |
| LCP | 4,124 ms | 2,000 ms未満 |
| 初期ロードJS | 565,290 B（gzip 172,362 B） | 旧サイト39,330 Bから削減 |

原因を調べたところ:

- 実ブラウザ（スロットリング無し）での LCP 要素は本文テキスト（`p.flagship__body`）で、**124 ms** で描画されていた。CLS は 0。
- Lighthouse の模擬スロットリング下では **LCP と TTI が 4,124 ms でぴったり一致**していた。つまりテキストの描画自体ではなく、**JS の実行完了を待たされている**状態だった。
- Lighthouse の指摘も `Reduce unused JavaScript: Est savings of 191 KiB`。
- 内訳を確認すると、最大のチャンク（229 KB）は **react-dom（ハイドレーション用）**。

このサイトは**クライアントコンポーネントを1つも持たない**（インタラクションが必要な箇所が無い設計）。つまりこの JS は「サーバーが生成したのと同一のマークアップを、ブラウザでもう一度描き直すだけ」で、画面上は何も変わらない。それが LCP を 4.1 秒まで押し下げていた。

### やったこと

ビルド後に `<script>` タグを取り除き、素の静的HTMLとして配信するようにした（`scripts/strip-hydration.mjs`）。リンクはすべて通常の `<a>` なので、これで壊れる機能は無い。

結果:

| | 除去前 | 除去後 |
|---|---|---|
| Performance | 87 | **100** |
| LCP | 4,124 ms | **1,504 ms** |
| 初期ロードJS | 565,290 B | **0 B** |
| 総転送量 | 559 KiB | **98 KiB** |

### 承知しておいてほしいこと

これは **Next.js が公式にサポートする使い方ではない**。将来インタラクションを追加したくなったときに問題になるので、次の安全装置を入れてある:

- `app/` `components/` `content/` を走査して `'use client'` を1つでも見つけたら、**除去処理を中止して警告を出す**（ビルドは通る）。
- その場合は `package.json` の build から `strip-hydration` の手順を外せば、通常の Next.js の挙動に戻る。

**より率直に言うと**: このサイトは Next.js の機能（クライアントサイドルーティング、サーバーコンポーネントの動的な組み立て、`next/image` の最適化など）をほぼ何も使っていない。1ページ・完全静的・インタラクション無しという最終的な仕様に対しては、Next.js はオーバースペックで、素の HTML/CSS のままか、あるいは Astro のような「既定でJSを出さない」構成の方が素直だった。Next.js 化はフェーズ1の確認で明示的に選ばれた方針なので**そのまま完遂した**が、この構成上のミスマッチは残っている。今後インタラクションを足す予定が無いなら、この点は認識しておいた方がいい。

- `animation-name` が `none` 以外の要素: **0 件**

## 7. 主な変更内容

### 情報設計
- スキル一覧の独立セクションを廃止し、技術名は各ケースの本文とタグに埋め込んだ
- フラッグシップ1件（紡シフト）を「課題 → やったこと → 技術的判断 → 結果」の流れで詳述
- その他の実績2件は、見出しを案件名ではなく**課題文そのもの**にした
- 日記機能と管理画面を削除
- 空疎な英語キャッチコピー（"Creating Digital Experiences"）を廃止し、日本語の具体的な一文に置き換えた

### 掲載可否の判断
- 紡シフトのバイト先店名は**確認待ちのため匿名**（`content/site.ts` の `subject` を差し替えれば反映される）
- インターン勤怠システムの金融機関名は非公開を継続。「不採用だった」という結果も隠さず記載
- 共同生活費レシート管理は、**認証が無く実データが入っているため掲載を見送り**
- その他の制作物はヌリミチを除く5件

### 技術
- Next.js 16 App Router / `output: 'export'`（クライアントコンポーネント0）
- `basePath` を環境変数で切替（GitHub Pages はサブパス `/portfolio`、Cloudflare Pages はルート）
- 見出し明朝体を**実使用145字のサブセット**に絞り自前ホスト。CSS 98,005→7,266 B、フォント 2,690,212 B（128ファイル）→ 77,032 B（7ファイル）
- 見出し文字がサブセットから漏れたら**ビルドを失敗させる**検証を追加（`scripts/verify-font-coverage.mjs`）
- 画像は sharp で WebP/AVIF 生成、実寸をマニフェストに書き出して `width`/`height` に使用

## 8. 残っている作業（本人の対応が必要）

### 8-1. デプロイ設定の変更（これをやらないと本番が壊れる）

現状、GitHub Pages も Cloudflare Pages も「リポジトリのルートをそのまま配信」する設定になっている。Next.js はビルドが必要なため、**両方の設定変更が必須**。これはアカウント設定の変更なので本人が行う必要がある。

1. **GitHub**: リポジトリ Settings → Pages → Build and deployment → Source を「Deploy from a branch」から **「GitHub Actions」** に変更する。ワークフローは `.github/workflows/deploy.yml` にコミット済み。
2. **Cloudflare Pages**: プロジェクト `portfolio` の設定で、ビルドコマンドに `npm run build`、出力ディレクトリに `out` を設定する（現在どちらも空欄）。

**この2つを変更する前に main へマージすると、両方のサイトが壊れる。**

### 8-2. 確認・判断が必要なもの

- **紡シフトのバイト先の店名**: 掲載可否をバイト先に確認する。可なら `content/site.ts` の `flagship.subject` を実名に差し替える
- **管理画面が無くなった**: コンテンツは `content/site.ts` を直接編集する形になった。編集UIが必要なら別途作る必要がある
- **共同生活費レシート管理**: アプリ側に認証を実装すれば掲載できる。その際は「URL の秘匿を事実上の認証代わりにしていたことに、ポートフォリオを作る過程で気づいて認証を入れた」という経緯自体が技術メモとして書ける
- **Windows実機での表示確認**: 本文フォントは Windows 環境を優先して調整したが、**Windows 実機での確認はできていない**（開発機が Mac で、Yu Gothic UI と Meiryo が存在しないことを実測で確認済み）。特に游ゴシックの細さと、明朝見出しの中の欧文（"LINE"、"Excel" 等）が小さく見えないかは実機で見てほしい
- **Next.js を使い続けるか**: 4章の通り、最終的な仕様に対して Next.js はオーバースペックになっている
