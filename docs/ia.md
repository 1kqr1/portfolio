## 3. ページ構成案（2案）

どちらも共通の前提: ナビゲーションは `ホーム / 作品 / 私について / お問い合わせ`。「スキル」は独立ページとして持たず、各ケーススタディの本文中に技術名を埋め込む。

### 案A：フラッグシップ1本 + インデックス型

```
┌─────────────────────────────────────┐
│ NAV: Home / Works / About / Contact  │
├─────────────────────────────────────┤
│  [氏名]                              │
│  [ポジショニング文 1〜2文]            │
│  （英語の大きなキャッチコピーではなく、 │
│    日本語で具体的な一文）              │
├─────────────────────────────────────┤
│  ── FEATURED ──                      │
│  紡シフト（フルケーススタディ）        │
│                                       │
│  課題（紙・LINE運用の何が辛かったか）  │
│    ↓                                 │
│  やったこと（企画〜運用、Excel出力対応 │
│  など固有要件、初めてD1を使った話）    │
│    ↓                                 │
│  結果（採用直後、社員の反応）           │
│                                       │
│  [スクリーンショット]                  │
├─────────────────────────────────────┤
│  ── その他の実績 ──                   │
│  ▸ DCCポータル                        │
│    50人規模コミュニティのプロフィール  │
│    自己編集をOIDC連携で実現            │
│    [詳細を見る]                       │
│  ▸ インターン勤怠・タスク管理          │
│    金融機関インターン向け。技術的には  │
│    完成、組織要件で不採用という経験    │
│    [詳細を見る]                       │
│  ▸ 共同生活費レシート管理              │
│    AI OCRで生活費の内訳を透明化         │
│    [スクリーンショットのみ]            │
├─────────────────────────────────────┤
│  ── その他の制作物 ──（軽量リスト）    │
│  DCC公式HP / オービス情報マップ /      │
│  献立アプリ / triNook / Focus Flight / │
│  ヌリミチ　（各1行 + リンク）          │
├─────────────────────────────────────┤
│  私について（学歴・簡単な経緯）         │
├─────────────────────────────────────┤
│  お問い合わせ                          │
└─────────────────────────────────────┘
```

**狙い**: 最初の1画面〜2画面で「課題→やったこと→結果」の1本の物語を読み切らせることで、"考え方の型"を強く印象づける。1本に集中する分、文章の密度を上げられる。

**この構成だと伝わらないこと**:
- 紡シフトは技術選定の理由が薄い実情なので、**技術力そのものの深さは最初の画面では伝わらない**（実行力・要件対応力は伝わるが）。
- BtoB業務改善／コミュニティ運営／個人開発、という3パターンの引き出しの広さは、スクロールしないと伝わらない。
- 就活で複数社に見せる場合、会社によって刺さる案件が違っても、常に同じ1本が最初に来る（会社ごとの出し分けはできない構造）。

### 案B：課題インデックス型（4件横並びリスト→個別ページ）

```
┌─────────────────────────────────────┐
│ NAV: Home / Works / About / Contact  │
├─────────────────────────────────────┤
│  [氏名]                              │
│  [ポジショニング文 1〜2文]            │
├─────────────────────────────────────┤
│  ── 解決してきた課題 ──                │
│  （3枚横並びカードではなく、1行1件の   │
│    縦積みインデックス。カード化しない） │
│                                       │
│  01を振らず、課題の一文そのものを見出し│
│  にする：                             │
│                                       │
│  「紙とLINEのシフト管理に限界を感じた  │
│   コワーキングスペースのために」        │
│   → 紡シフト　[React/Cloudflare D1]   │
│  ─────────────────────────           │
│  「金融機関のインターン勤怠管理を、    │
│   紙とExcelから」                     │
│   → インターン勤怠システム             │
│  ─────────────────────────           │
│  「50人のコミュニティに、自分の作品を  │
│   自分で編集できる場所を」             │
│   → DCCポータル                       │
│  ─────────────────────────           │
│  「割り勘のたびに揉めていた生活費を、  │
│   AIで見える化」                      │
│   → 共同生活費レシート管理             │
│                                       │
│  各行クリックで個別ページ              │
│  （/works/tsumugi-shift 等）へ         │
├─────────────────────────────────────┤
│  ── その他の制作物 ──（軽量リスト）    │
├─────────────────────────────────────┤
│  私について / お問い合わせ             │
└─────────────────────────────────────┘

  ↓ 個別ページ（例: /works/tsumugi-shift）
┌─────────────────────────────────────┐
│  ← 作品一覧に戻る                     │
│  紡シフト                             │
│  課題 / 担当範囲 / やったこと / 結果 / │
│  技術メモ　を全部このページで深掘り     │
└─────────────────────────────────────┘
```

**狙い**: 最初の1画面で4パターンの課題文だけをテンポよく並べることで、「幅広い引き出し」を最速で伝える。見出しを課題文そのものにすることで、`01/02/03`のような意味のない連番を避けつつ視線誘導できる。

**この構成だと伝わらないこと**:
- 見出し（課題文）だけで満足して離脱する訪問者には、**実装の中身・技術的な深さがまったく伝わらない**（クリック率に強く依存する構造）。
- 4件が横並びで並ぶため、「どれが一番自信作か」という優先順位が伝わりにくい（案Aは強制的に1本目立たせるが、案Bは4件がフラットになりがち）。
- 個別ページが増える分、実装・デザインの一貫性を保つコストが上がる（Next.js移行と合わせるとルーティング設計が必要になる）。
